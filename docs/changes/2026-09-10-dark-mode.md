# Dark Mode

## Before

`globals.css` already had a complete `.dark` CSS-variable palette defined (`--background`, `--foreground`, `--muted`, `--primary`, etc.) and every `ui/` primitive (`Button`, `Input`, `Avatar`, `Card`) already referenced those variables — but nothing ever applied the `.dark` class, there was no toggle, and almost every page/feature component hardcoded raw light-only Tailwind colors (`bg-white`, `text-black`, `text-gray-400`, `bg-gray-100`, ...) directly instead of the theme tokens. Toggling `.dark` alone would have changed nothing visible.

## Requested

Full sweep: real dark mode across the whole app in one pass, not just a toggle.

## Implemented

### Toggle infrastructure

- Installed `next-themes`. `client/src/app/providers.tsx` now wraps the app in `<ThemeProvider attribute="class" defaultTheme="system" enableSystem>`.
- `client/src/app/layout.tsx`: added `suppressHydrationWarning` to `<html>` (required by next-themes, since the real theme is only known client-side after reading localStorage/system preference).
- New `client/src/components/theme-toggle.tsx` — a sun/moon icon button using `useTheme()`, with a `mounted` guard to avoid a hydration mismatch (renders a disabled placeholder until mounted, then the real toggle). Added to the self-profile actions row on `/profile/[username]`, next to Edit Profile / Requests / Get Verified.

### The actual sweep

Went through every page/component with hardcoded colors and replaced them with the existing semantic tokens (already wired into Tailwind via `@theme inline` in `globals.css`), rather than bolting on `dark:` variants everywhere:

| Raw class | Replaced with |
|---|---|
| `bg-white` (page/sticky headers, modal surfaces) | `bg-background` |
| `text-black` (active nav state) | `text-foreground` |
| `text-gray-400` / `text-gray-500` / `text-gray-600` (secondary text, loading states, timestamps) | `text-muted-foreground` |
| `bg-gray-100` (image placeholders, incoming chat bubble, thumbnails) | `bg-muted` |
| `bg-gray-50` (row hover) | `hover:bg-muted` |
| `bg-gray-300` (dashed avatar border, seen-story ring) | `border-border` / `bg-muted` |
| `border-white` / `ring-white` (avatar separator rings) | `border-background` / `ring-background` |
| `bg-black` (own-story "+" badge) | `bg-foreground` with `text-background` icon - correctly inverts per theme instead of staying literally black |
| `bg-black text-white` / `bg-gray-100 text-black` (chat bubbles: mine / theirs) | `bg-primary text-primary-foreground` / `bg-muted text-foreground` |
| `bg-blue-50` (unread notification row) | `bg-blue-50 dark:bg-blue-950/40` (no direct semantic token for this one, so a manual dark variant) |

Files touched: `bottom-nav.tsx`, `stories-bar.tsx`, `post-card.tsx`, `post-modal.tsx`, `comment-section.tsx`, `home/page.tsx`, `explore/page.tsx`, `notifications/page.tsx`, `chat/page.tsx`, `chat/[username]/page.tsx`, `profile/[username]/page.tsx`, `profile/page.tsx`, `profile/edit/page.tsx`, `profile/requests/page.tsx`.

**Deliberately left alone**: `call-overlay.tsx` and `story-viewer.tsx` (full-screen `bg-black` immersive overlays - standard convention for call/story UIs, correct in both themes by design, not a light-mode bug), `verified-badge.tsx` (`fill-blue-500`/`text-white` is the badge's own brand color, not a page surface), status-color badges (`bg-red-500` unread counters, `text-red-500` error text - readable on both themes as accent colors), and `app/page.tsx` (unused Next.js starter boilerplate, not part of the real app, already had its own `dark:` classes from the template).
